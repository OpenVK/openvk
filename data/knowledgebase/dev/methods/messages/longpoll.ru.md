# User Long Poll API

**Long Polling** — это технология, позволяющая клиентскому приложению получать мгновенные уведомления о новых сообщениях и событиях в режиме реального времени через постоянное HTTP-соединение («длинные запросы»).

Сервер удерживает входящий HTTP-запрос открытым до тех пор, пока для текущего пользователя не произойдет хотя бы одно событие (новое сообщение, прочтение, набор текста, изменение статуса онлайн и т.д.), либо пока не истечет таймаут ожидания (`wait`). Как только событие происходит или таймаут истекает, сервер немедленно возвращает ответ, после чего клиент обрабатывает полученные данные и сразу отправляет следующий запрос с обновленным номером временной метки (`ts`).

---

## 1. Схема работы

Работа с Long Poll состоит из трёх этапов:

```
[Клиент] --- 1. messages.getLongPollServer (lp_version=3) ---> [OpenVK API]
[Клиент] <-- 2. { server, key, ts, pts } ---------------------- [OpenVK API]

[Клиент] --- 3. GET https://{server}?act=a_check&key=...&ts=... -> [LongPoll Сервер]
              ... (соединение удерживается до 25 сек) ...
[Клиент] <-- 4. { ts: new_ts, updates: [ ... ] } --------------- [LongPoll Сервер]

[Клиент] --- 5. Повторный GET с новым ts ----------------------> [LongPoll Сервер]
```

### Шаг 1: Получение данных для подключения
Перед началом работы клиент вызывает метод **[messages.getLongPollServer](/dev/methods/messages/getLongPollServer)** с указанием желаемой версии протокола:

```http
POST /method/messages.getLongPollServer HTTP/1.1
Host: openvk.instance
Content-Type: application/x-www-form-urlencoded

lp_version=3&need_pts=1&access_token=YOUR_ACCESS_TOKEN&v=5.138
```

Ответ API возвращает параметры сессии:

```json
{
    "response": {
        "key": "4f9a0c7e2b1d",
        "server": "openvk.instance/nim",
        "ts": 1820350874,
        "pts": 450
    }
}
```

### Шаг 2: Отправка запроса к Long Poll серверу
Клиент отправляет GET-запрос к полученному адресу сервера:

```http
GET https://openvk.instance/nim?act=a_check&key=4f9a0c7e2b1d&ts=1820350874&wait=25&mode=2&version=3 HTTP/1.1
Host: openvk.instance
```

### Шаг 3: Обработка ответа
Сервер возвращает новую временную метку `ts` и массив произошедших событий `updates`:

```json
{
    "ts": 1820350910,
    "updates": [
        [
            4,
            1619489,
            561,
            2000000001,
            1710000000,
            "Привет!",
            { "title": "Беседа", "from": 123 },
            { "attach1_type": "photo", "attach1": "1_100" },
            18492048,
            42
        ]
    ]
}
```

## 2. Параметры запроса к Long Poll серверу

| Параметр | Тип | Обязательный | Описание |
| --- | --- | --- | --- |
| `act` | string | **Да** | Всегда значение `a_check`. |
| `key` | string | **Да** | Секретный ключ сессии, полученный из `messages.getLongPollServer`. |
| `ts` | integer | **Да** | Номер последнего полученного события. В первом запросе передается значение `ts`, полученное из `messages.getLongPollServer`, а в последующих — значение `ts` из предыдущего ответа сервера. |
| `wait` | integer | **Да** | Максимальное время ожидания события в секундах (рекомендуется `25`, максимум `90`). |
| `mode` | integer | Нет | Битовая маска дополнительных опций возвращаемых данных (сумма флагов). По умолчанию: `2`. |
| `version` | integer | Нет | Версия протокола Long Poll (`1`, `2` или `3`). По умолчанию: `2`. |

### Флаги параметра `mode`

Параметр `mode` формируется как сумма желаемых битовых флагов:
* `+2` — возвращать объект вложений и метаданных (`attachments`) в событиях новых и обновленных сообщений;
* `+8` — возвращать расширенный набор событий (в протоколе v0 возвращает событие `101` со структурой объекта сообщения);
* `+32` — возвращать параметр `pts` в ответе сервера (требуется для синхронизации через `messages.getLongPollHistory`);
* `+64` — в событии `8` (онлайн пользователя) возвращать код платформы в поле `$extra`;
* `+128` — возвращать поле `random_id` в событиях сообщений;
* `+256` — возвращать внутренний локальный ID беседы (`minor_id` / `conversation_message_id`).

## 3. Ошибки Long Poll (`failed`)

Если сессия прервана или история устарела, Long Poll сервер возвращает объект с кодом `failed`:

| Код | Ответ сервера | Описание ошибки и действие клиента |
| --- | --- | --- |
| `1` | `{"failed": 1, "ts": ...}` | Временная метка `ts` устарела или пропущена. Обновите `ts` на значение из ответа и повторите запрос. |
| `2` | `{"failed": 2}` | Истёк срок действия ключа `key`. Запросите новые параметры подключения через **[messages.getLongPollServer](/dev/methods/messages/getLongPollServer)**. |
| `3` | `{"failed": 3}` | Информация о сессии утрачена на сервере. Заново вызовите **[messages.getLongPollServer](/dev/methods/messages/getLongPollServer)** и возобновите опрос с новыми `key` и `ts`. |
| `4` | `{"failed": 4, "min_version": 1, "max_version": 3}` | Передана неподдерживаемая версия протокола в параметре `version`. Укажите поддерживаемую версию (от `1` до `3`). |

> **Рекомендация по обработке `failed: 1`:** При потере событий из-за устаревшего `ts` рекомендуется использовать метод **[messages.getLongPollHistory](/dev/methods/messages/getLongPollHistory)** по параметру `pts`, чтобы загрузить пропущенные сообщения.

## 4. Три протокола Long Poll (Версии 1, 2 и 3)

В OpenVK поддерживаются три версии протокола User Long Poll. Версия выбирается параметром `version` при запросе к серверу и параметром `lp_version` при вызове `messages.getLongPollServer`.

Главные различия версий заключаются в **структуре события `4` (новое сообщение)**, адресации бесед (`peer_id`) и наборе поддерживаемых событий.

---

### Версия 1 (v1 — Legacy / VK API < 5.80)

Классический устаревший протокол времен VK API 5.20 и ранних клиентов.

#### Особенности v1:
* **Адресация бесед (`peer_id`):** Для групповых бесед из идентификатора назначения вычитается смещение `2000000000`. Таким образом, передается локальный `chat_id` (от `1` до `N`), а не `2000000000 + chat_id`. Для личных сообщений передается `user_id`.
* **Событие 4 (Новое сообщение):**

```json
  [
      4,
      "$message_id",
      "$flags",
      "$peer_id",
      "$timestamp",
      "$subject",
      "$text",
      "$attachments"
  ]
```

Где:

  1. `$message_id` *(integer)* — глобальный идентификатор сообщения.
  2. `$flags` *(integer)* — битовая маска флагов сообщения (см. раздел «Флаги сообщений»).
  3. `$peer_id` *(integer)* — идентификатор автора или беседы (для чатов: `chat_id` без `2000000000`).
  4. `$timestamp` *(integer)* — Unix-время отправки сообщения.
  5. **`$subject`** *(string)* — заголовок темы или имя беседы (обычно пустая строка `""` или `" ... "`).
  6. **`$text`** *(string)* — текст сообщения (находится на **6-й** позиции!).
  7. `$attachments` *(object, при mode=2)* — карта вложений со строковыми ключами (`attach1_type`, `attach1`, `from` и т.д.).
* **События 6 и 7 (Прочтение сообщений):**
  `[6, $peer_id, $local_id]` и `[7, $peer_id, $local_id]` — передаются без счетчика оставшихся сообщений.
* **Набор текста:** Передаются устаревшие события `61` (для ЛС) и `62` (для бесед).

---

### Версия 2 (v2 — Промежуточная / VK API 5.38 — 5.79)

Протокол с единой адресацией диалогов и поддержкой редактирования сообщений.

#### Особенности v2:
* **Адресация бесед (`peer_id`):** Для бесед всегда передается полный `peer_id` со смещением: `2000000000 + chat_id`. Для сообществ передается отрицательный ID: `-group_id`.
* **Событие 4 (Новое сообщение):**

```json
[
    4,
    "$message_id",
    "$flags",
    "$peer_id",
    "$timestamp",
    "$subject",
    "$text",
    "$attachments",
    "$random_id"
]
```

  Порядок основных полей сохранён из v1 (сначала `$subject`, затем `$text`), но в конец добавляется поле `$random_id` (при `mode=128`).
* **Событие 5 (Редактирование сообщения):**
  `[5, $message_id, $mask, $peer_id, $timestamp, $new_text, $attachments, $stub]` — уведомление об изменении текста или вложений сообщения.
* **Массовое удаление и восстановление:** Добавлены события `13` (`[13, $peer_id, $local_id]`) и `14` (`[14, $peer_id, $local_id]`).

---

### Версия 3 (v3 — Современная / VK API >= 5.80) — Рекомендуется

Актуальный стандарт Long Poll, используемый всеми современными клиентами и ботами.

#### Особенности v3:
* **Критическое отличие в событии 4 (Новое сообщение):**
  Порядок полей оптимизирован — **текст сообщения перемещён на 5-ю позицию**, а тема заменена на структурированный объект `$extra_fields`:

```json
[
    4,
    "$message_id",
    "$flags",
    "$peer_id",
    "$timestamp",
    "$text",
    "$extra_fields",
    "$attachments",
    "$random_id",
    "$conversation_message_id"
]
```

Где:

  1. `$message_id` *(integer)* — глобальный идентификатор сообщения.
  2. `$flags` *(integer)* — маска флагов сообщения.
  3. `$peer_id` *(integer)* — полный идентификатор диалога (`user_id`, `2000000000 + chat_id`, `-group_id`).
  4. `$timestamp` *(integer)* — время отправки (Unix timestamp).
  5. **`$text`** *(string)* — **текст сообщения** (перемещен на 5-ю позицию!).
  6. **`$extra_fields`** *(object)* — служебный объект:
     * `title` *(string)* — имя беседы;
     * `from` *(integer)* — реальный идентификатор автора сообщения при отправке в беседу.
  7. **`$attachments`** *(object)* — ассоциативный массив вложений и метаданных.
  8. **`$random_id`** *(integer)* — клиентский `random_id`.
  9. **`$conversation_message_id`** *(integer)* — локальный номер сообщения внутри беседы (`conversation_message_id`).
* **События 6 и 7 (Прочтение сообщений):**
  Добавлен 4-й параметр `$count` — число оставшихся непрочитанных сообщений в диалоге:
  * `[6, $peer_id, $local_id, $count]` — прочтение входящих;
  * `[7, $peer_id, $local_id, $count]` — прочтение исходящих.
* **Набор текста и голосовых сообщений (Мультитайпинг):**
  Вместо устаревших кодов 61/62 используются события 63 и 64, поддерживающие список участников:
  * `[63, $user_ids, $peer_id, $total_count, $ts]` — пользователи набирают текст;
  * `[64, $user_ids, $peer_id, $total_count, $ts]` — запись голосового сообщения.
* **Синхронизация состояния:** Добавлены события `20` (`[20, $peer_id, $major_id]`) и `21` (`[21, $peer_id, $minor_id]`) для отслеживания изменений метаданных диалога.

| --- | --- | --- | --- |
| **v1** (Legacy) | `v < 5.80` | Индекс 6 (после темы) | Беседы адресуются локальным `chat_id` (1...N). События 6/7 без счетчика. Формат сообщений `VKApiMessageLegacy`. |

## 5. Формат структуры сообщений (toVkApiStruct vs toVkApiStructLegacy)

При синхронизации сообщений через метод **[messages.getLongPollHistory](/dev/methods/messages/getLongPollHistory)** (а также в методах `messages.get`, `messages.getHistory`), формат возвращаемых объектов в массиве `messages.items` зависит от версии API:

### Современный формат (API v >= 5.80 — `VKApiMessage`)
Используется модель бесед `peer_id` и локальных номеров `conversation_message_id`:

```json
{
    "id": 1619489,
    "conversation_message_id": 42,
    "date": 1710000000,
    "peer_id": 2000000001,
    "from_id": 123,
    "text": "Привет всем!",
    "out": 0,
    "read_state": 1,
    "random_id": 18492048,
    "important": false,
    "attachments": [ ... ],
    "reply_message": { ... },
    "fwd_messages": [ ... ]
}
```

* Текст передается в поле **`text`**;
* Идентификатор отправителя — **`from_id`**;
* Диалог назначения — **`peer_id`**;
* Цитата ответа передается структурированным объектом в **`reply_message`**.

### Устаревший формат (API v < 5.80 — `VKApiMessageLegacy`)
Используется классическая модель диалогов с полями чата:

```json
{
    "id": 1619489,
    "user_id": 123,
    "date": 1710000000,
    "read_state": 1,
    "out": 0,
    "title": "Беседа",
    "body": "Привет всем!",
    "chat_id": 1,
    "chat_active": [123, 456, 789],
    "users_count": 3,
    "admin_id": 123,
    "emoji": 0,
    "deleted": 0,
    "attachments": [ ... ],
    "fwd_messages": [ ... ]
}
```

* Текст передается в поле **`body`** (а не `text`);
* Адресат/автор передается в поле **`user_id`**;
* Номер группового чата передается в поле **`chat_id`** (без смещения 2000000000);
* Ответы и цитаты передаются как пересланные сообщения в **`fwd_messages`**.

## 6. Флаги сообщений (`flags`)

Флаг сообщения представляет собой целочисленную битовую маску (сумму флагов):

| Флаг | Название | Описание |
| --- | --- | --- |
| `+1` | `UNREAD` | Сообщение не прочитано получателем. |
| `+2` | `OUTBOX` | Исходящее сообщение (отправлено текущим пользователем). |
| `+4` | `REPLIED` | На сообщение был создан ответ (цитата). |
| `+8` | `IMPORTANT` | Сообщение помечено как важное. |
| `+16` | `CHAT` | Сообщение отправлено внутри групповой беседы. |
| `+32` | `FRIENDS` | Сообщение отправлено другом. |
| `+64` | `SPAM` | Сообщение помечено как спам. |
| `+128` | `DELETED` | Сообщение удалено для текущего пользователя. |
| `+256` | `FIXED` | Сообщение проверено пользователем на спам. |
| `+512` | `MEDIA` | Сообщение содержит медиавложения. |
| `+65536` | `HIDDEN` | Приветственное или скрытое сервисное сообщение. |
| `+131072` | `DELETE_FOR_ALL` | Сообщение удалено для всех участников беседы. |

#### Пример проверки флагов в коде:

```python
is_unread = bool(flags & 1)
is_outbox = bool(flags & 2)
is_important = bool(flags & 8)
```

## 7. Вложения и метаданные (`attachments`)

При передаче флага `mode=2` в запросе к Long Poll, в событиях новых (`4`) и обновленных (`5`) сообщений передается объект `attachments`:

| Поле | Пример значения | Описание |
| --- | --- | --- |
| `attach{$i}_type` | `"photo"`, `"video"`, `"audio"`, `"doc"`, `"sticker"`, `"wall"` | Тип `$i`-го вложения (`i >= 1`). |
| `attach{$i}` | `"1_456239017"` | Идентификатор `$i`-го медиавложения в формате `{owner_id}_{id}`. |
| `attach{$i}_product_id` | `123` | Идентификатор стикера (для `attach{$i}_type=sticker`). |
| `from` | `12345` | Идентификатор реального автора сообщения при отправке в беседу. |
| `reply` / `reply_to` | `4512` | Идентификатор сообщения, на которое сделан ответ. |
| `fwd` | `"1_10,1_11"` | Идентификаторы пересланных сообщений через запятую. |
| `emoji` | `1` | Флаг наличия эмодзи в тексте. |
| `source_act` | `"chat_create"`,<br>`"chat_title_update"`,<br>`"chat_invite_user"`,<br>`"chat_kick_user"`,<br>`"chat_pin_message"` | Сервисное действие в групповой беседе. |
| `source_mid` | `12345` | Идентификатор затронутого пользователя для сервисного действия. |

## 8. Полный список кодов событий Long Poll

| Код | Формат массива события | Описание |
| --- | --- | --- |
| `0` | `[0, msg_id, 0]` | Удаление сообщения `msg_id`. |
| `1` | `[1, msg_id, flags, peer_id]` | Замена всех флагов сообщения на `flags`. |
| `2` | `[2, msg_id, mask, peer_id]` | Установка флагов сообщения по маске `mask` (`flags \|= mask`). |
| `3` | `[3, msg_id, mask, peer_id]` | Сброс флагов сообщения по маске `mask` (`flags &= ~mask`). |
| `4` | *Зависит от версии протокола (см. раздел 4)* | Добавление нового сообщения. |
| `5` | `[5, id, mask, peer, ts, text, attach]` | Редактирование текста или вложений сообщения. |
| `6` | `[6, peer_id, local_id, count]` | Прочтение входящих сообщений в `peer_id` вплоть до `local_id`. |
| `7` | `[7, peer_id, local_id, count]` | Прочтение исходящих сообщений в `peer_id` вплоть до `local_id`. |
| `8` | `[8, -user_id, extra, ts]` | Пользователь `user_id` стал онлайн. Младший байт `extra & 0xFF` содержит ID платформы. |
| `9` | `[9, -user_id, flags, ts]` | Пользователь `user_id` стал оффлайн (`flags`: 0 — выход, 1 — таймаут). |
| `10` | `[10, peer_id, mask]` | Сброс флагов диалога `peer_id` (для сообществ). |
| `11` | `[11, peer_id, flags]` | Замена флагов диалога `peer_id` (для сообществ). |
| `12` | `[12, peer_id, mask]` | Установка флагов диалога `peer_id` (для сообществ). |
| `13` | `[13, peer_id, local_id]` | Удаление всех сообщений в диалоге `peer_id` вплоть до `local_id`. |
| `14` | `[14, peer_id, local_id]` | Восстановление удаленных сообщений в `peer_id` вплоть до `local_id`. |
| `20` | `[20, peer_id, major_id]` | Глобальное изменение истории сообщений в диалоге (требуется сброс кеша клиента). |
| `21` | `[21, peer_id, minor_id]` | Изменение метаданных диалога (закрепленное сообщение, название и т.д.). |

## 9. Пример реализации Long Poll клиента (Python)

Ниже представлен пример цикла опроса Long Poll сервера с автоматической обработкой ошибок и разбором входящих сообщений (протокол **v3**):

```python
import requests
import time

TOKEN = "YOUR_ACCESS_TOKEN"
API_URL = "https://openvk.instance/method/"

def get_lp_server():
    """Получение параметров подключения к Long Poll серверу"""
    resp = requests.post(API_URL + "messages.getLongPollServer", data={
        "lp_version": 3,
        "need_pts": 1,
        "access_token": TOKEN,
        "v": "5.138"
    }).json()
    
    if "error" in resp:
        raise Exception(f"API Error: {resp['error']}")
    return resp["response"]

def listen_longpoll():
    server_info = get_lp_server()
    server = server_info["server"]
    key = server_info["key"]
    ts = server_info["ts"]
    
    if not server.startswith("http"):
        server = f"https://{server}"

    print(f"Connected to LongPoll: {server}, ts={ts}")

    while True:
        try:
            url = f"{server}?act=a_check&key={key}&ts={ts}&wait=25&mode=2&version=3"
            response = requests.get(url, timeout=35).json()

            # Обработка системных ошибок
            if "failed" in response:
                code = response["failed"]
                if code == 1:
                    ts = response["ts"]
                    print(f"Failed 1: TS updated to {ts}")
                elif code in (2, 3):
                    print("Failed 2/3: Session expired, reconnecting...")
                    server_info = get_lp_server()
                    server = server_info["server"]
                    key = server_info["key"]
                    ts = server_info["ts"]
                    if not server.startswith("http"):
                        server = f"https://{server}"
                continue

            # Обновление временной метки для следующего запроса
            ts = response.get("ts", ts)

            # Обработка событий
            for event in response.get("updates", []):
                code = event[0]

                # Событие 4: Новое сообщение (в версии 3)
                if code == 4:
                    msg_id = event[1]
                    flags = event[2]
                    peer_id = event[3]
                    timestamp = event[4]
                    text = event[5]
                    extra_fields = event[6] if len(event) > 6 else {}
                    attachments = event[7] if len(event) > 7 else {}
                    cmid = event[9] if len(event) > 9 else None

                    is_outbox = bool(flags & 2)
                    sender_id = extra_fields.get("from", peer_id)

                    print(f"[{'Исходящее' if is_outbox else 'Входящее'}] "
                          f"peer={peer_id} sender={sender_id} (msg_id={msg_id}, cmid={cmid}): {text}")

        except requests.RequestException as e:
            print(f"Network error: {e}. Retrying in 3 seconds...")
            time.sleep(3)

if __name__ == "__main__":
    listen_longpoll()
```
