# Участие в разработке OpenVK

OpenVK — открытый проект, разрабатываемый сообществом под свободной лицензией **GNU AGPLv3**. Мы приветствуем помощь: исправление багов, оптимизацию, добавление новых возможностей и обновление документации.

---

## 1. С чего начать и рабочий процесс Git

Вся разработка ведется на GitHub в репозитории [openvk/openvk](https://github.com/openvk/openvk).

1. **Сделайте Fork:** создайте форк репозитория `openvk/openvk` в свой аккаунт на GitHub.
2. **Клонируйте форк локально:**
```bash
git clone https://github.com/<ваш-логин>/openvk /opt/openvk
cd /opt/openvk
```
3. **Создайте отдельную ветку** от актуального `master`:
```bash
git checkout -b fix/user-settings-validation
```
4. **Внесите и протестируйте изменения.**
5. **Сделайте коммит с понятным описанием:**
```bash
git commit -m "Fix profile avatar upload validation on PHP 8.4"
```
6. **Отправьте ветку в ваш форк и откройте Pull Request** в ветку `master`.

---

## 2. Требования к коду и стандарты разработки

Чтобы кодовая база оставалась чистой и поддерживаемой, все изменения должны соответствовать следующим правилам:

### Бэкенд (PHP)
* **Версия PHP:** код должен быть полностью совместим с **PHP 8.4+**.
* **Строгая типизация:** каждый PHP-файл обязан начинаться с директивы:

```php
<?php

declare(strict_types=1);
```

* **Стандарты PSR:** соблюдайте стандарт оформления кода **PSR-12** (отступы в 4 пробела, camelCase для методов, PascalCase для классов).
* **Типизация:** обязательно указывайте типы аргументов, возвращаемых значений функций и PHPDoc-комментарии при необходимости.

### Фронтенд (JavaScript)
* Пишите чистый модульный код на **ES6+**.
* Не добавляйте тяжелые сторонние библиотеки без веской необходимости.
* Скрипты располагаются в `Web/static/js/`.

### Шаблоны (Latte) и CSS
* Для шаблонизации интерфейса используется шаблонизатор **Latte** (`Web/Presenters/templates/`).
* Таблицы стилей оформляются на чистом **Vanilla CSS** (`Web/static/css/`) в соответствии с существующими классами.

---

## 3. Обязательное требование к документации

При добавлении нового функционала или изменении существующего:

* **Методы API:** если вы добавляете или изменяете метод API, вы **обязаны** создать или обновить документацию в `data/knowledgebase/dev/methods/` (на английском `.md` и русском `.ru.md` языках).
* **Модели данных:** обновляйте описания структур в `data/knowledgebase/dev/models/`.
* **Локализация (i18n):** все новые строковые ресурсы интерфейса должны быть добавлены одновременно в `locales/en.strings` и `locales/ru.strings`.

---

## 4. Тестирование перед отправкой

Перед созданием Pull Request убедитесь:

1. В отсутствии синтаксических ошибок PHP:
```bash
php -l путь/к/измененному/файлу.php
```
2. В корректности миграций базы данных:
```bash
./openvkctl upgrade
```
3. В работоспособности интерфейса и API-запросов.
4. В отсутствии предупреждений (Warnings/Notices) в логах PHP-FPM или сервера.

---

## 5. Процесс ревью и слияния

После создания Pull Request мейнтейнеры проекта проведут код-ревью. После утверждения ваши изменения будут объединены с веткой `master`.
